Checked against the code on 2026-11-17 (commit `a720737`); technical debt (section 8) and the entries changed by the 2026-11-24 work updated on 2026-11-25; first written on 2026-10-08, after the DHIS2 login and route protection work (commit `9f66b09`). Items marked *(audit 2026-11-27)* come from a docs-versus-code audit of that day (full suite run, AST scripts, code read). ## 1. Security

1. *Removed (2026-10-23):* `DELETE /output/reset` and its `.output_sig` "signature" (no caller in etlui; opening a run empties `output/`). Forecast containers run as the worker's user (`forecast_runner._container_user`) and `output/` is created by the worker before `docker run`. Files left root-owned by older runs must be handed back once (`GETTING_STARTED.md`, "output/ owned by root").
2. *Fixed (2026-10-16):* SSRF through `webhook_url`. Every route takes the `WebhookUrl` type (`api/routers/__init__.py`): https to a host of `WEBHOOK_ALLOWED_HOSTS` only, 422 otherwise; empty list = every webhook refused. `notify_webhook` uses httpx, which does not follow redirects. *Unverified:* a DNS name of the allow-list that resolves to an internal address is still called.
3. *Fixed (2026-10-16):* `/validate_inputs` free paths. Its paths and `input_dir` take the `InputPath` type shared with `ForecastParams` (file path under `input/`, no `..`, no leading `-`). Since 2026-11-27 the use case resolves them in the mode's folder under `DATA_DIR` (`work_dir`), like the rest of the code.
4. *Fixed (2026-11-17):* a login or a logout while a job holds the pipeline lock no longer revokes the DHIS2 token that job read at its start (`api/auth/router.py`, `_job_running`); the token is only dropped from Redis and expires on its own (30 days at most since 2026-11-26), so etlhub may leave a few valid tokens it no longer knows. Still possible: a job still running when its token reaches its 30-day expiry gets 401 from DHIS2 (no timeout on jobs, by decision).
5. *Removed (2026-11-17):* roles. No admin check anywhere (`require_admin`, `is_admin`, `ADMIN_ONLY` deleted, etlui shows the Journal's CSV export and Job lock zone to everyone): every logged-in user of a host in `DHIS2_ALLOWED_HOSTS` may call every route, and the last one to log in is the DHIS2 identity of every job. Decided, not an issue.
6. *Fixed (2026-11-17):* request logs (SQLite `logs/etlhub.db`, 30 days) store the URL with the value of `webhook_url` masked (`api/middleware.py`, `_logged_url`: `webhook_url=[redacted]`, the other query parameters are kept for the tracking page and the journal). Bodies and headers are not logged, so the login password and cookies are not. A new free-text query parameter that can carry a secret must be masked there too.
7. *Fixed (2026-10-08):* a client `X-Request-ID` is kept only if it is a UUID (`api/middleware.py`, `_request_id`), so it can no longer overwrite another entry.
8. **P3 — The DHIS2 tokens are in clear in Redis** (`dhis2:credential:<username>`, one per account) and in its AOF/RDB files. Accepted: `redis.conf` binds to localhost, requires a password, and the data directory must stay `chmod 700`. Since 2026-11-26 each token lives 30 days, the browser session 24 h; a token is revoked at its account's logout or when the account logs in from another browser.
9. *Decided (2026-11-27): kept public*: `GET /`, `/docs`, `/redoc`, `/openapi.json` (the full API map), and `/auth/dhis2-urls`.
10. *Fixed (2026-11-25):* the forecast temp env file is gone: the container gets no `.env` at all, no network, no capability but `SYS_NICE`, and its image by digest (`decision-design/forecast-sandbox/`).

Fixed (2026-10-08): every router except `auth_router` requires the session, the log WebSocket included (origin check, close `4401`), guarded by `tests/api/test_route_protection.py` · `GET /api/config/` no longer returns the DHIS2 token · OAuth routes, `/auth/validate-token` and `JWT_SECRET` removed · login sends credentials only to `DHIS2_ALLOWED_HOSTS` · failed login after revoking the previous token no longer leaves it active in Redis.

Bypasses inside `infrastructure` (allowed by the rule): `tasks.py` builds `JobStore()` and calls `get_checkpoint_store()` directly.

*Fixed (2026-11-27, owner's decisions, `decision-design/hexagonal-review/`):* `tests/test_architecture.py` missed crossings. It now walks every source file (layers, `core/`, root files), resolves relative and `from etlhub import x` imports, lets `application` read only `core.config`, `core.job_context`, `core.request_context`, and checks third-party libraries per layer (ETL copies per file; `ingestion_service.py` → `pridec_gee.AVAILABLE_VARIABLES` accepted). The crossings it now refuses were fixed behind ports: `FetchedImports` injected into `fetch_pivot` / `gee_import` (B2); `EventSubscriber` for the log WebSocket (B3); `AuthStoreUnavailable` instead of `redis.RedisError` in `api/auth/router.py`; `DHIS2Accounts` for the login's DHIS2 client; `OutputFiles` for the report and archive; `WebhookNotifier`; `DHIS2Reader` and `ImportSettings` for the availability check. Nothing under `api/` imports `redis`, `httpx` or `etlhub.infrastructure`. Limits: the guard reads import statements only (not `importlib`, nor a client passed in), and allows the whole stdlib (`subprocess`, `urllib.request`, `socket`, `sqlite3` in `application`, `domain` or `api` would pass). Was: the guard walked 4 folders, skipped relative imports, never flagged `core`, ignored third-party libraries; `fetch_pivot.py` used `core.dependencies` as a service locator, the WebSocket built its own Redis pool, the auth router caught `redis.RedisError`, `dhis2_auth.py` held an `httpx` client.
