# UI components: migration to shadcn-vue

> Status: **decided 2026-10-27, lots 1 to 5 implemented.** Replaces parts of
> `../tailwind-migration/tailwind-migration.md` (see § 2).

## 1. What

etlui takes its UI components from [shadcn-vue](https://www.shadcn-vue.com) (Vue port of shadcn/ui, built on
Reka UI). shadcn-vue is not a library imported whole: its CLI **copies the source** of each component asked for into
`src/components/ui/<name>/`. Only the components etlui uses are added, and the code is ours to edit.

## 2. Decisions

| # | Decision | Replaces |

| S1 | Replace etlui's hand-made components by their shadcn-vue equivalent, **one lot at a time** (§ 4). | — |

Lot 6 follows the OS and adds the header toggle (D3), writing the same class. | tailwind-migration `data-theme` attribute, § 3.2 |
| S5 | Icons: **`@lucide/vue`** (successor of the deprecated `lucide-vue-next`). `Icons/Icon.vue` goes once every use is migrated. | tailwind-migration § 6 "no icon pack" |
| S6 | Toasts stay on `vue3-hot-toast` for now. | — |

Kept from tailwind-migration: D1 (gray), D2 (indigo), D3 (light + dark, toggle), D4 + § 3.5 (`data-test` in specs,
never a styling class), § 3.4 (state through `aria-*` / `data-state`), D7 (CSS only where utilities cannot reach).

## 3. Setup (lot 1)

- CLI: `shadcn-vue@2.8.2`. It **needs Node ≥ 22**: etlui pins Node 22 in `.nvmrc` (same as the `Dockerfile`), run `nvm use` first.
  Yarn 1 has no `dlx`: run the CLI through `npx`, it detects `yarn.lock` and installs with yarn (no `package-lock.json`).
  ```sh
  nvm use && npx shadcn-vue@2.8.2 add <component>
  ```
- `components.json`: style `new-york`, base color `neutral` (the CLI refuses `gray`; the values are replaced by
  gray in `base.css`), `iconLibrary: lucide`, aliases `@/components/ui`, `@/lib/utils`. The `font` key was removed:
  with it, every `add` prepends a second Google Fonts `@import` for Inter to `base.css` (`index.html` already loads it).
- Dependencies added: `reka-ui`, `class-variance-authority`, `cn` (shadcn's replacement for `clsx` +
  `tailwind-merge`), `@lucide/vue`, `@vueuse/core` (lot 3, used by `Input` and `Label`), `tw-animate-css` (dev).
- The root `.gitignore` ignores every `input/` (pipeline files): `!etlui/src/components/ui/input/` keeps shadcn's `Input` tracked.
- A scoped `<style>` that `@apply`s a shadcn token (`border-input`…) must `@reference` `src/styles/base.css`, not `"tailwindcss"` (which only knows the default theme): see `ConfigView.vue`.
- `base.css`: the `chart-*` and `sidebar-*` tokens generated by the CLI were removed (nothing uses them). A
  component that needs them brings them back through `add`.
- `base.css` now applies `border-border` to every element and `bg-background text-foreground` to `body` (shadcn
  base layer): an element with `border` and no color class now gets `--border` instead of `currentColor`.

### 4.1 Dialogs (lot 4)

Why together:

Today's dialogs are native `<dialog>` + `showModal()`: they live in the browser's **top layer**. Reka dialogs are
rendered in a portal under `<body>` with a `z-index`, which never reaches the top layer. A Reka dialog opened from a
native one (a `ConfirmDialog` from the Steps dialog, the report from the Steps dialog) would sit **below** it,
behind an inert page. Mixed, they break; so all of them switch in one lot.

What the switch changed, and the fixes it needed:
- **Closed = unmounted.** A native `<dialog>` kept its content in the DOM; a Reka dialog renders it only while open, a
  tick after `open` turns true. Safe here: the Steps dialog's state (`files`, `shown`) lives in `LevelColumn`. Lost
  on close: a `FileDropzone`'s wrong-extension message.
- **Tests.** `src/test/setup.ts` stubs `teleport` with a pass-through component (`teleport: true` stubbed Reka's own
  `Teleport` and rendered nothing), so the content stays in the mounted wrapper. Specs `await flushPromises()` after
  opening, select `[role="dialog"]` / `data-test` instead of `dialog`, and `exists()` instead of the `open` attribute.
- **Stacking.** A portal's content sits where its `Teleport` was mounted, not where it was opened: the Dashboard's
  dialogs (preview, confirmation, report) are mounted before a run's Steps dialog, so at an equal `z-50` the Steps
  dialog covered them (seen in headless Chrome). `components/ui/dialog/openOrder.ts` gives each dialog the next
  z-index when it opens (`DialogContent`, `AlertDialogContent`). Checked by `ui/dialog/__tests__/DialogContent.spec.ts`
  and in the browser.
- **Global CSS through the portal.** `ForecastRuns`' unscoped CSS is `.forecast-runs .steps-dialog …`; the Steps
  content is wrapped in `<div class="forecast-runs"><div class="steps-dialog">` (`ponytail:` comment, goes with the
  ForecastRuns restyle).
- **Toasts.** The `popover="manual"` layer stays (top layer, above every dialog); `raiseToasts()` is gone. A click on a
  toast is a click outside for Reka: `DialogContent.vue` cancels the dismiss when the target is in `[data-toasts]`.
- **Scrolling.** The dialog body scrolls, not `DialogContent`, so shadcn's absolute close cross stays visible
  (`RequestDialog`, Steps).

### 4.2 Widgets (lot 5)

Local edits to the copied components, each marked `etlui:` in the file:
- `table/TableCell.vue`: no `whitespace-nowrap` by default. With it, the Journal's event details stopped wrapping and
  pushed Actor / Request out of view (seen in headless Chrome); cells that must not wrap say so.
- `progress/Progress.vue`: the indicator divides by `max`; shadcn's assumed `max = 100` (a run's "3 of 9" drew 3 %).
  Checked by `progress/__tests__/Progress.spec.ts`.

In the views:
- `Accordion` keeps closed sections mounted (`unmount-on-hide` off): collapsing Forecasts must not drop a file picked
  but not uploaded.
- `Select`: Reka refuses `''` as an item value; `'all'` (Journal) and `'default'` (Config `LOG_LEVEL`) stand for it.
- `CsvPreview` keeps a native `<table>` with the shadcn parts inside: `Table` wraps the table in an `overflow-auto` div,
  which would become the scroll container of its sticky header and columns. Checked in Chrome: the header stays at
  the top after scrolling.
- A scoped rule on a class passed to `Table` (`.availability-table { … }`) no longer matches (the class is on the inner
  `<table>`, the scope attribute on the wrapper): its box styles are utilities now.
- Specs: open a `Select` with Enter on the trigger and pick with Enter on the `[role="option"]`; click
  `[role="checkbox"]`; radios are `[role="radio"]`; the progress bar is `[role="progressbar"]` (`aria-valuenow`,
  `aria-valuemax`).
