# UI components: migration to shadcn-vue

> Status: **decided 2026-10-27, lots 1 and 2 implemented.** Replaces parts of
> `../tailwind-migration/tailwind-migration.md` (see § 2).

## 1. What

etlui takes its UI components from [shadcn-vue](https://www.shadcn-vue.com) (Vue port of shadcn/ui, built on
Reka UI). shadcn-vue is not a library imported whole: its CLI **copies the source** of each component asked for into
`src/components/ui/<name>/`. Only the components etlui uses are added, and the code is ours to edit.

## 2. Decisions

| # | Decision | Replaces |
|---|---|---|
| S1 | Replace etlui's hand-made components by their shadcn-vue equivalent, **one lot at a time** (§ 4). | — |
| S2 | **shadcn tokens** (`--background`, `--primary`, `--muted`, `--border`…) in `src/styles/base.css`, with Tailwind **gray** values and one **indigo** accent (`--primary`). | tailwind-migration D5 (`surface`, `accent`… tokens), § 3.1 |
| S3 | Components are **Vue components** (`Button`, `Dialog`…) with `variant` / `size` props. | tailwind-migration D6 (`.btn`, `.card` classes), § 3.3 |
| S4 | Dark theme = **`.dark` class on `<html>`** (shadcn convention, `@custom-variant dark (&:is(.dark *))`). Set by `main.ts` from the OS today; the header toggle (D3) will write the same class. | tailwind-migration `data-theme` attribute, § 3.2 |
| S5 | Icons: **`@lucide/vue`** (successor of the deprecated `lucide-vue-next`). `Icons/Icon.vue` goes once every use is migrated. | tailwind-migration § 6 "no icon pack" |
| S6 | Toasts stay on `vue3-hot-toast` for now. | — |

Kept from tailwind-migration: D1 (gray), D2 (indigo), D3 (light + dark, toggle), D4 + § 3.5 (`data-test` in specs,
never a styling class), § 3.4 (state through `aria-*` / `data-state`), D7 (CSS only where utilities cannot reach).

## 3. Setup (lot 1)

- CLI: `shadcn-vue@2.8.2`. It **needs Node ≥ 22**: etlui pins Node 22 in `.nvmrc` (same as the `Dockerfile`), run `nvm use` first.
  Yarn 1 has no `dlx`: run the CLI through `npx`, it detects `yarn.lock` and installs with yarn (no `package-lock.json`).
  ```sh
  nvm use && npx shadcn-vue@2.8.2 add <component>
  ```
- `components.json`: style `new-york`, base color `neutral` (the CLI refuses `gray`; the values are replaced by
  gray in `base.css`), `iconLibrary: lucide`, aliases `@/components/ui`, `@/lib/utils`. The `font` key was removed:
  with it, every `add` prepends a second Google Fonts `@import` for Inter to `base.css` (`index.html` already loads it).
- Dependencies added: `reka-ui`, `class-variance-authority`, `cn` (shadcn's replacement for `clsx` +
  `tailwind-merge`), `@lucide/vue`, `tw-animate-css` (dev).
- `base.css`: the `chart-*` and `sidebar-*` tokens generated by the CLI were removed (nothing uses them). A
  component that needs them brings them back through `add`.
- `base.css` now applies `border-border` to every element and `bg-background text-foreground` to `body` (shadcn
  base layer): an element with `border` and no color class now gets `--border` instead of `currentColor`.

### Why the dialogs move together (lot 4)

Today's dialogs are native `<dialog>` + `showModal()`: they live in the browser's **top layer**. Reka dialogs are
rendered in a portal under `<body>` with a `z-index`, which never reaches the top layer. A Reka dialog opened from a
native one (a `ConfirmDialog` from the Steps dialog, the report from the Steps dialog) would sit **below** it,
behind an inert page. Mixed, they break; so all of them switch in one lot.

Also for lot 4:
- Specs that look inside a dialog must search `document.body` (portal), not the component wrapper.
- The `popover="manual"` toaster and `BaseDialog` re-showing it after `showModal()` exist only because of the top
  layer. With Reka dialogs the toaster may no longer need the popover: check it, do not assume.
